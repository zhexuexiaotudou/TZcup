# 3 天操作员认证接口

## 1. 目标

把 `codex/day1-value-package` 中已经存在的三日培训课程转换成一个可直接执行、可审计、拒绝伪造的认证接口。

本文件不重复课程内容。课程、教练配置和安全门以该分支的 `application-value-package/01-operator-training.md` 为准。

## 2. 证据等级

| 等级 | 允许结论 |
|---|---|
| `CURRICULUM` | 存在课程和验收表，不能证明新手掌握 |
| `INTERNAL_REHEARSAL` | 项目成员演练过，不能代表目标用户 |
| `USER_QUEUE` | 未参与开发的目标用户完成课程，可报告真实结果 |
| `FIELD_ACCEPTED` | 用户队列与现场运行均通过并签署验收 |

当前等级为 `CURRICULUM`。

## 3. 认证数据契约

每名匿名操作员、每个考核项至少记录：

| 字段 | 说明 |
|---|---|
| `operator_id` | 匿名编号，不使用姓名、手机号或其他非必要个人信息 |
| `day` | 1、2 或 3 |
| `item_id` | 冻结的考核项编号 |
| `category` | `safety` 或 `operation` |
| `rating` | `A` 独立、`B` 一次提示后完成、`C` 不能完成 |
| `prompt_count` | 必要提示次数，不能手工隐藏 |
| `critical_error` | `true` 或 `false` |
| `evidence_path` | 录像、签字表或系统日志 |

## 4. 通过判据

建议在训练开始前冻结以下规则：

1. 所有 `safety` 项必须为 `A`，且 `critical_error=false`。
2. `operation` 项中 `A/B` 比例不低于 90%。
3. 任一关键安全错误直接不通过，不能用总分抵消。
4. 第三天结束前通过才计入“3 天掌握”；复训通过另列。
5. 必须报告队列数、未完成/退出人数，不能只报告通过者。

## 5. 当前可写入报告

> 项目已建立三日操作员培训、安全门和结构化验收台账，并定义了从匿名用户数据计算“3 天掌握率”的规则。当前尚无真实目标用户队列，因此该指标保持 `NOT_MEASURED`。

不能写：

> 新手可在 3 天内掌握。
