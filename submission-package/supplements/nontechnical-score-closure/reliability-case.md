# 日均故障率 <1% 的统计资格计划

## 1. 当前状态

项目已有短时仿真、板端回放和失败记录，但没有可持续运行的车辆日分母，因此当前为 `INSTRUMENTED_NOT_MEASURED`。

本包冻结事件字典和统计方法，不把短窗结果换算成日均故障率。

## 2. 分母

主口径建议使用“车辆日”：

- 一辆车开始当天首个任务并产生日志，记为一个车辆日；
- 当天因计划维护、培训或客户主动停用，不记为运行车辆日；
- 因车辆自身无法出勤的故障，即使没有开始任务，也必须记入故障并保留在分母审计中；
- 计数周期、时区和日界线在开窗之前冻结。

也可同时报告每任务和每 100 运行小时指标，但不能在开窗后选择最有利分母。

## 3. 故障定义

`data/reliability-event-dictionary.json` 给出机器可读分类。主故障集合至少包括无法启动、非计划任务中止、安全接管、关键传感器失效、定位丢失导致停车、通信失效、控制失效、机械堵塞无法自动恢复、制动异常和电池异常。

计划维护、正常满箱、人工主动暂停和客户场地停电可以排除，但必须保存判定理由。

## 4. 置信资格

若 n 个车辆日中出现 k 个主故障，使用二项分布单侧 95% 上界。只有在下列情况之一成立时，才可主张“95% 置信上界低于 1%”：

| 观测到的主故障数 k | 至少需要的车辆日 |
|---:|---:|
| 0 | 299 |
| 1 | 473 |
| 2 | 628 |

这些数字只表示统计资格门槛，不是已经运行的天数。

## 5. 必备日志

- 车辆、软件、地图和硬件版本；
- 任务开始、结束、中止和接管事件；
- 故障类别、严重度、发现方式、恢复方式和恢复时间；
- 原始时间戳、时区和仿真/墙钟标识；
- 被排除事件及排除理由；
- 每天日志完整性和缺失小时数。

## 6. 当前可写入报告

> 项目已定义车辆日事件字典和单侧 95% 二项上界算法；在零主故障条件下，至少需要 299 个有效车辆日才能把故障率上界压到 1% 以下。当前尚无长期运行分母，因此日均故障率仍为 `NOT_MEASURED`。
