# 仓库产物策略

## 目标

仓库保存可运行源码和可审计的紧凑证据，不保存可重新生成的大型中间产物。这样既保留结论依据，也避免克隆、检出和发布包被日志或数据集拖慢。

## 可以提交

- 评审后的指标 JSON、状态 JSON 和小型 YAML 配置；
- 逐文件 SHA-256 清单、命令摘要和环境摘要；
- 解释结论所必需的少量图表；
- 经许可且运行时确实需要的小型模型或地图；
- `*_review`、`*_evidence` 等明确命名的紧凑证据目录。

## 不进入 Git

- `build/`、`install/`、`log/`、`.work/` 和 Python 缓存；
- MCAP、DB3、完整 rosbag、逐帧图像、训练集和原始音频；
- Docker overlay、第三方 SDK、工具链安装包和可重新下载的依赖；
- 重复运行日志、失败尝试工作目录、逐点大 CSV 和临时模型；
- 包含个人信息、密钥、令牌或未经许可第三方资产的文件。

## 运行与收敛

原始产物写入 `.gitignore` 覆盖的本机目录。阶段完成后，由 finalize 工具生成紧凑 evidence；提交前检查清单、哈希、敏感信息和结论边界。当前结论写入 `docs/current-status.md` 或对应专题文档，历史过程由 Git、PR 和 evidence 保留；README 只保留项目入口与稳定能力边界。

删除已经进入历史的原始产物只会缩小当前检出和发布包，不会改写既有 Git 历史；需要追溯时可按清理前提交恢复。除非另行授权，不做破坏性的历史重写。
