# Journey 6 board-arrival runbook

Do not change perception semantics when the board arrives. The accepted order
is:

1. connect power, console, and an isolated network;
2. collect read-only board inventory;
3. import and hash the board-matched official J6 BSP/OpenExplorer package;
4. lock actual SKU, march, runtime, sysroot, and available BPU cores;
5. run the vendor AIBenchmark or official sanity HBM;
6. select a matching precompiled project profile or compile the frozen
   canonical ONNX and calibration manifest for that march;
7. compare static-image ONNX/HBM outputs;
8. deploy into the inactive slot and run health checks;
9. atomically activate the candidate;
10. connect live sensors and the formal ROS/IPC gateway;
11. run Ethernet HIL latency, 30-minute stability, fault, and rollback gates;
12. run the competition 30-seed matrix only after all preceding gates pass.

Inventory examples:

```bash
python3 scripts/j6_board_inventory.py --output J6_BOARD_INVENTORY.json
```

Deployment examples are generated by the bundle tooling. The actual command
must include the board IP/user and a verified bundle path; `Profile auto` is
resolved only from inventory. A mismatch stops deployment.

Only deployment-layer changes needed for an official ABI difference are
allowed after freeze. Class mapping, thresholds, NMS, RGB-D projection,
tracking, ActionVerifier, DynamicTrashMap, re-observation, spot/post-clean, and
safety gates remain unchanged.
