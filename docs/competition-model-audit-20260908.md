# 比赛目标下的地图与整车模型审计

审计基线为 `main@fe17b31`。正式车辆入口是
`formal_competition_vehicle.urdf.xacro`，不是历史缩比车；地图以
`sanitation_campus_scenario` 生成场景和正式首次建图/保存地图链为准。
本次检查覆盖展开模型的 196 个 link、195 个 joint、258 个碰撞几何体，
并对照 `formal_goal_acceptance_crosswalk.json` 的 A01–A08 等目标。

## 确认的问题和修复

| 问题 | 比赛影响 | 处理 |
|---|---|---|
| 静态地图忽略 link yaw 对 collision 局部平移的旋转 | 地图障碍与 Gazebo 实体错位 | 按 model/link/collision 层级组合二维变换；不能准确处理的姿态、嵌套模型和外部 include 明确拒绝，防止漏掉实体障碍 |
| 圆柱 keepout 使用内接 16 边形 | 柱体边缘和声明安全余量被截掉 | 使用外接多边形，并检查整个圆周包含性 |
| 百分比限速像素再经 0.25/0.65 阈值缩放 | 50% 被解为约 63%，部分低限速变为零值 | scale 模式采用 0/1 阈值，检查全部整数百分比的实际解码 |
| 收纳 footprint 比真实碰撞体小 | 侧刷及后部鱼眼支架可能在导航判空时碰撞 | 两个允许行驶姿态统一为 x=[-0.610,0.620]、y=[-0.695,0.695] m；同步布局和 costmap inflation |
| 升降机构中间/越界位置被当作收纳 | 机构未收起时选择错误状态 | 只有接近零位才可认定升起，其他状态保守处理 |
| 手臂和清扫子总成的静态包络过小 | 布局台账无法包住实际收纳结构 | 按展开碰撞体的前向运动学修正包络 |
| 1.32 m 实心圆盘覆盖估算与清扫模型不符 | 把未扫到的地面计入清扫完成率 | 作为未鉴定估算隔离，不能作为正式有效覆盖通过证据 |

静态地图修复作用于显式 public-static-map materializer。正式首次建图设置
`materialize_static_maps=false`，由 SLAM 产生产品占据地图；不能把这里的修复
描述为已经修复或验证在线 SLAM 精度。

## 清扫宽度仍有实质缺口

根据当前 URDF 的实际圆柱和 `GroundDirtCleaningSystem` 的清扫判定，直线行进的
横向清扫区间为 `[-0.695,-0.395]`、`[-0.310,0.310]`、`[0.395,0.695]` m。
外侧跨度 1.39 m，区间总宽 1.22 m，最大连续宽度只有 0.62 m；中间存在两条
0.085 m 漏扫带。插件没有横向搬运垃圾的物理机制，不能假设侧刷会自动把这两条带扫净。

因此 0.60 m 最低清洁宽度有名义几何支持，但不是实测清洁效果通过；1.32 m 仍只是
待验证目标，不是当前模型已经证明的连续有效宽度。新增
`audit_formal_vehicle_competition_geometry.py` 将这些量分别报告，并拒绝在漏扫带
未解决时把宽度状态改成通过。其顶层 `passed` 仅表示包络和声明边界检查通过。

后续可按真实清扫形状规划更密的条带并实测覆盖，或重新设计刷盘/滚刷布置。
增大滚刷、外移部件或改变侧刷半径涉及干涉、载荷、功率和地面接触，不能凭空修改
供应商尺寸冒充机械修复。3500 m²/h 必须继续按同次运行的有效面积并集除以总时间验收。

## 尚未消除的滚刷与前轮实体干涉

滚刷和前轮的 URDF 碰撞体都是轴线平行于 y 的实心圆柱，可以直接判定是否相交，
无需凭 AABB 猜测。滚刷圆柱半径 0.100 m、长度 0.620 m，中心为
`(0.155,0,0.200)` m（升起）或 `(0.155,0,0.100)` m（工作）；前轮半径
0.1651 m、长度 0.1143 m，中心为 `(0.256,±0.2829,0.1651)` m。

每侧轴向区间重叠 0.08425 m；两圆柱轴线在 x-z 平面的距离，升起时约
0.10686 m、工作时约 0.12017 m，均小于半径之和 0.2651 m。
所以四个组合均存在**实际建模实体交集**，不是保守包络误报。新增几何报告将
`model_mechanical_layout_clear` 保持为 false；包络通过不再可能被解释为机构无干涉。
具体证据点 `(0.20,±0.26,0.15)` m 在两个升降状态下都同时位于滚刷和相应前轮的圆柱内部。

本次没有通过缩小轮胎碰撞体、禁用碰撞、隐藏滚刷或随意平移单个 visual 掩盖问题。
消除干涉需要同步重新布置滚刷、电机、轴承、护罩和承载安装架，并重新核算质量、
升降全行程和与侧刷/底盘的间隙。当前名义满载裕量仅约 30 g，不能在没有新的质量和
结构依据时随意增加安装架。此项机械布局整改尚未完成，整车模型不能被称为无干涉或实物可建造。

既有 FOV 和惯量/机械臂采样门仍按其原合同执行；它们不等于完整部件配对干涉检查。
`static_preflight_complete` 表示检查已执行完整，不表示机械设计或制造通过。

## 保留的边界

- 正式地图具有 20,000 m² 面积；map0 为 200×100 m，其余地图有意改变长宽比。
- 地面灰尘、落叶和积水视觉目标不等于 CFD、颗粒输运或真实清洁效果；独立水回收门另行验收。
- 单树、质量、正定惯量和有限姿态几何检查不能证明连续机械臂全空间安全。
- 包络和 inflation 增大后，部分旧路线的可通行性可能改变；共享 Nav2 基础配置的演示场也需回归，不能用旧导航成绩替代。
- 名义满载只剩约 0.030417 kg 载荷余量；S100P 外形、孔位、线束和实际质量仍需测量，不能称为实车制造就绪。
- 原始运行和 session 证据保持不变。模型合同变化后，必须用新的 source/runtime/closure
  重跑 footprint、首次建图、保存地图、清扫和安全等受影响门。
- 本机冷启动资源门因可用提交内存低于 12.5 GiB 拒绝 WSL；当前修复没有 Gazebo/Stage
  运行验收，不改变比赛仿真、S100P 或实车通过状态。
