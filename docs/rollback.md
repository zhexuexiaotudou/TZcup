# 发布与回滚

产品发布只能从已合并、CI 通过且 A–P 验收为真的 `origin/main` 精确提交生成。发布记录必须包含提交 SHA、容器 digest、依赖锁、模型与配置哈希、ZIP SHA-256、生成时间和完整证据索引。

当前验收未通过，因此没有可部署的 V1 产品发布包，也没有生产部署回滚点。

正式发布后，直接回滚点是上一条已通过相同验收合同的 `main` 发布提交。回滚步骤为：

1. 停止目标版本并保全日志、bag 和故障现场。
2. 校验上一发布包的 SHA-256、签名和来源提交。
3. 恢复与该提交匹配的配置、模型、容器 digest 和依赖锁。
4. 按项目部署手册恢复服务并执行健康检查与关键用户路径验证。
5. 通过新的 PR 使用 `git revert` 修复主线，保留审计历史；不得在共享仓库执行破坏性重置。
