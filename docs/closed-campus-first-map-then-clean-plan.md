# 20,000 m²级虚拟封闭半结构化园区：首次建图、后续清扫方案

> 状态：URDF无关研发闭环已实现并完成组件/ROS/Gazebo验收；正式竞赛级高保真整车已完成规划和条件可行性评估，但真实URDF/CAD、实际模型推理、板端部署、建图定位接线和正式多任务统计仍待后续完成。

## 1. 已确定的总体设定

- 构建一个不小于 `200 m × 100 m`、有效面积不小于 `20,000 m²`、由geofence虚拟封闭但四周无实体围墙的园区测试场地。
- 园区是存在建筑、园路、广场、绿化和固定设施的半结构化环境，但没有供车辆依赖的车道线或预设行车路线；车辆在可通行自由空间内作业。
- 场地整体近似平面，但通过建筑墙面、内部围栏、电线杆、路灯、垃圾桶、树木、花坛、长椅、设备箱等静态物体形成接近真实园区的视觉效果、通行约束和激光定位特征。
- 车辆每次从固定停靠点启动。停靠点在地图坐标系中的位置已知，可作为初始化先验，但不得直接用仿真真值代替真实定位过程。
- 定位与建图主要使用二维激光雷达、GNSS、轮速计，并建议继续使用现有 IMU 提高短时姿态和航向稳定性。
- 首次任务以探索和建图为主，清扫机构关闭；地图通过验证并固化后，后续任务加载该地图并进行高效率全覆盖清扫。

## 2. 场景设计

### 2.1 空间布局

场地采用“geofence虚拟封闭的园区自由空间”而非“道路交通场景”。建议划分以下区域，但区域之间不使用车道线限定车辆运动：

1. 固定起点与停靠区：包含充电桩或车棚、唯一形状的定位标志物和足够的初始化空间。
2. 建筑区：布置数栋尺寸、朝向和外形不同的房屋，形成墙面、转角、通道和 GNSS 遮挡。
3. 开阔区：保留较大广场，用于检验激光特征稀疏时 GNSS 与里程计对定位的支撑能力。
4. 设施区：布置电线杆、路灯、垃圾桶、长椅、设备箱等离散物体，提供近距离激光特征。
5. 绿化与边界区：使用树木、花坛和内部围栏形成不规则可清扫区域；场地外边界仅由geofence定义，不设置实体园区围墙。
6. 窄通道与回转区：在建筑、花坛或设施之间形成不同宽度的通道，用于验证阿克曼车辆的通过性与转弯规划。

场景应避免大量完全相同、等间距排列的物体，以降低重复几何导致的激光匹配歧义。定位参考物应符合真实园区布置逻辑，不能为了让算法通过而人为铺设密集路标。

### 2.2 资产来源与工程约束

- 优先使用 Gazebo/Open Robotics 自带资产、Gazebo Fuel 中许可清晰的开源资产，以及现有 SDF 基础几何体。
- 外部资产在纳入项目时必须记录来源、版本、许可证和文件哈希，并缓存到本地，正式复现不得依赖运行时联网下载。
- 每个资产应明确属于以下一种或多种用途：视觉装饰、碰撞约束、激光定位特征。
- 视觉模型与碰撞模型允许简化，但碰撞边界不得明显侵入或放大实际可通行区域。
- 最终有效建图区域必须独立核算，场景外围装饰或服务区不计入 `20,000 m²` 指标。

## 3. 定位与建图方案

### 3.1 传感器职责

| 传感器 | 主要作用 | 典型薄弱场景 |
|---|---|---|
| 二维激光雷达 | 建立占据栅格、匹配建筑边缘及杆状/箱状设施、抑制局部漂移 | 大面积空旷区、重复结构、玻璃或弱反射表面 |
| GNSS | 提供全局位置约束，限制长距离累计漂移 | 建筑遮挡、多路径、瞬时跳变 |
| 轮速计 | 提供连续局部运动估计 | 打滑、急转弯、湿滑地面、轮径误差 |
| IMU（建议保留） | 改善航向变化和短时运动估计 | 偏置、磁干扰或长期积分漂移 |

融合原则是：轮速计和 IMU 保证局部连续性，激光匹配环境几何，GNSS约束全局漂移。GNSS或激光质量下降时应增大对应不确定度，而不是继续输出虚假的高置信定位。

### 3.2 首次任务：探索建图

1. 车辆从固定停靠点启动，完成传感器时间同步、坐标外参和健康检查。
2. 使用停靠点先验、GNSS和局部里程计建立地图坐标初值。
3. 采用边界探测、前沿探索与分区遍历相结合的策略探索未知空间，避免只沿园区外围行驶。
4. 在开阔区、建筑转角、窄通道和 GNSS 遮挡区安排必要的闭环路径。
5. 持续检查未知区域、可达区域和定位置信度，直至满足建图完整性条件。
6. 保存占据栅格、位姿图、地图元数据、场地边界、禁行区以及传感器/软件版本信息。
7. 完全重启定位与导航系统，加载保存地图，从固定停靠点重新定位。
8. 通过若干分布在园区各处的验证点和闭环路线确认地图可复用；通过后才将其提升为正式清扫地图。

首次任务不承担清扫覆盖率和清扫效率指标，清扫机构保持关闭，以便把失败明确归因于探索、定位或建图环节。

首次建图阶段忽略垃圾和地面脏污语义：不生成DynamicTrashMap、DirtyAreaMap或定点清扫任务，也不把脏污写入正式静态地图。若离散垃圾在LiDAR中形成临时障碍，只允许进入当前局部障碍层并随观测清除，不能固化成永久地图结构。

### 3.3 后续任务：基于已有地图定位

- 启动时加载已验证的固定地图，以停靠点先验给出初始位姿，再由激光、GNSS、轮速计和 IMU 完成一致性校验与持续定位。
- 固定地图描述长期静态环境；临时人员、车辆或杂物进入局部代价地图，不直接改写正式地图。
- 建筑墙面、内部围栏或固定设施发生明显变化时，应生成新地图版本并重新完成验证，不能静默覆盖当前正式地图。
- 控制链路不得使用 Gazebo 真值位姿；真值只可用于离线评分和误差分析。

## 4. 全覆盖清扫方案

### 4.1 可清扫区域生成

从正式占据地图和园区geofence生成可清扫多边形，扣除建筑、内部围栏、花坛、固定设施、禁行区及车辆安全膨胀半径。规划使用真实清扫刷有效宽度，而不是仅按车体中心轨迹计算覆盖。

### 4.2 规划策略

1. 对不规则自由空间进行单元分解，优先采用适合全覆盖任务的往复式/牛耕式分解。
2. 每个单元沿其长轴生成平行清扫带，减少转弯次数和无效行驶距离。
3. 根据阿克曼转向半径，为相邻清扫带生成可行连接；必要时使用有限倒车，但记录并限制倒车次数。
4. 在清扫带、区域和连接顺序上联合优化，优先连续完成邻近区域，减少跨区空驶。
5. 转场、掉头和避障绕行时根据实际策略关闭或管理清扫机构，避免把非有效作业轨迹计入覆盖率。
6. 动态障碍由局部规划器避让；障碍移开后，对遗留未覆盖区域安排补扫。
7. 以清扫刷扫掠栅格持续记录已覆盖、遗漏和重复覆盖区域，任务结束前执行补漏，并返回固定停靠点。

### 4.3 效率优化方向

- 清扫带方向优先与区域长边一致。
- 通过分区排序、跳带连接和回转预留区减少阿克曼车辆频繁原地式掉头需求。
- 主效率按任务启动至清扫完成终态的底盘实际轨迹总长度核算，包含有效清扫、转场、避障和补扫里程；等待时间、能耗及完成后的返航距离不进入主指标，墙钟时间只作辅助诊断。
- 支持任务中断后的分区级恢复，避免重扫整个场地。

## 5. 系统数据流

```text
首次任务：
LiDAR + GNSS + 轮速计 + IMU
        -> 局部里程计与全局约束融合
        -> SLAM / 探索
        -> 占据地图 + 位姿图 + 场地元数据
        -> 重启、重载、重定位验证
        -> 正式地图版本

后续任务：
正式地图 + 当前传感器
        -> 重定位与持续定位
        -> 可清扫区域 / 全局代价地图
        -> 全覆盖规划
        -> Nav2 与车辆控制
        -> 清扫刷扫掠记录
        -> 补漏、完成判定、返航
```

现有项目可继续复用阿克曼车辆模型、SLAM Toolbox、GNSS/轮速/IMU融合框架、Nav2、安全控制和扫掠覆盖审计；本方案主要改变大型正式场景的环境假设和任务组织方式，不要求删除现有小型、中型演示场景。

## 6. 建议的验收口径

以下指标在实施前仍需结合赛题正式口径冻结：

- 场景：有效边界内面积不小于 `20,000 m²`，不存在车辆依赖的结构化道路或预设路线，资产许可和版本可追溯。
- 探索：对所有安全可达区域完成探索，未知区域比例和不可达区域均可解释。
- 地图：能够保存、完全重启、重载并从固定停靠点重新定位；地图版本和输入配置可复现。
- 定位：在开阔区、设施密集区、窄通道和 GNSS 遮挡区分别评估，正式目标按赛题要求验证，不能只报告全程平均误差。
- 清扫：按清扫刷实际扫掠面积统计有效覆盖率、漏扫率、重复覆盖率和碰撞情况。
- 效率：按包含转弯、避障和补扫的任务底盘实际轨迹总长度统计，并与相同随机任务的全覆盖基线配对比较；等待时间、能耗和完成后的返航距离仅辅助报告。
- 鲁棒性：通过多随机种子、动态障碍、GNSS降级、轮速打滑和局部环境变化测试，禁止用单次成功代替稳定性结论。

## 7. 实施前需要冻结的参数

1. 场地有效边界是精确 `200 m × 100 m`，还是在两个方向留出额外余量。
2. 建筑、绿化、设施和开阔区各自的大致面积比例。
3. GNSS正常区、遮挡区和多路径干扰区的分布及误差模型。
4. 是否将 IMU 列为正式必需传感器，而非仅作为推荐配置。
5. 允许使用的外部资产库、许可证范围及本地缓存策略。
6. “探索完成”的未知栅格阈值、最小可达通道宽度和不可达区域标注规则。
7. 清扫刷宽度、安全距离、最小转弯半径、允许倒车次数和停靠精度。
8. 动态障碍物类型、数量、速度及其是否计入清扫效率考核。
9. 场景结构变化达到何种程度时必须重新建图。

## 8. 开放词汇垃圾与脏污感知方案

### 8.1 感知在系统中的定位

系统保留两种作用域：全覆盖基线模式与垃圾感知解耦，不等待识别结果，也不因漏检跳过区域；强化学习按需清扫模式则以感知生成的Belief Map、脏污区域和离散目标作为规划输入，允许跳过尚未发现脏污的区域，但仍必须完成至少95%的有效观察。两种模式的LiDAR安全避障均保持独立，任何视觉模型或策略都不能绕过Collision Monitor、禁行区或边界保护。

感知目标分为两类：

| 类型 | 示例 | 主要输出 | 处理方式 |
|---|---|---|---|
| 离散物体垃圾 | 塑料瓶、金属罐、纸张、包装物 | 类别、检测框、置信度、三维位置；可选实例掩膜 | 开放词汇目标检测为主，确认后进入定点清扫 |
| 地面区域脏污 | 落叶堆、灰尘、积水、泥污 | 地面掩膜、地图坐标多边形、面积和置信度 | 开放词汇/提示分割为主，生成区域加强清扫任务 |

### 8.2 模型约束

- 只使用公开预训练权重，不对感知模型进行微调、增量训练或领域训练。
- 允许固定文本提示词、类别同义词、输入分辨率和置信度阈值，但这些配置只能在开发集上选择并冻结，不能利用最终测试集反复调参。
- 模型原始权重、源代码 revision、许可证、导出配置、板端产物和文件哈希必须可追溯。
- “不微调”不等于“不验收”。必须用代表性 Gazebo 图像和独立真实 RGB-D 样本测量零样本性能；未达到指标时应关闭对应语义功能，而不是宣称通过。

### 8.3 SAM 3与RDK S100支持结论

截至本方案记录时，未在 D-Robotics 官方 RDK S100 文档、Model Zoo S 或 TROS 示例中找到可直接运行的 SAM 3/SAM 3.1 BPU 模型、HBM转换方案或 ROS 2部署示例。因此不能把“低帧率运行SAM 3”写成已具备的板端能力；降低帧率不能解决模型尚未转换和算子兼容性未知的问题。

Meta 官方 SAM 3/SAM 3.1仍可作为PC/CUDA侧的零样本能力上限对照，但不进入S100基线，也不直接拥有车辆控制权。

当前候选的S100支持边界为：

1. **DOSOD + EdgeSAM（已选定的PC闭环基线，S100部署待验证）**：D-Robotics官方 `mono_edgesam` 明确支持S100，并提供订阅上游检测框后分割以及组合启动示例；但DOSOD官方仓库当前给出的板端转换与预编译示例是RDK X5，未确认S100 HBM/TROS部署链。因此DOSOD负责开放词汇候选检测、EdgeSAM负责掩膜的架构保持不变，但不能提前声称整条链已支持S100。
2. **YOLOE-11s-Seg Prompt-Free**：D-Robotics Model Zoo S提供S100参考模型和运行示例，可同时产生检测结果与实例掩膜，适合作为结构最简单的单模型候选。官方页面明确把它标为探索性案例，因此其板端性能数据不能代替本项目精度验收。
3. **EdgeTAM**：D-Robotics提供S100/S100P提示初始化和视频跟踪分割示例。它适合在低频检测/分割初始化后传播掩膜，但本身不理解垃圾文本类别，必须由上游检测结果提供提示。

### 8.4 冻结的候选架构

```text
PC能力对照（不作为S100部署证据）：
RGB -> Grounding DINO或开放YOLO检测 -> SAM 3.1分割 -> 零样本参考结果

PC闭环基线及S100目标架构（DOSOD的S100移植仍是硬门）：
RGB/NV12 -> DOSOD
         -> 离散垃圾框直接进入跟踪
         -> 区域候选框送入EdgeSAM生成掩膜

S100备选（仅在基线失败时重新裁决）：
RGB/NV12 -> YOLOE-11s-Seg Prompt-Free -> 检测框 + 实例掩膜

可选时序增强：
低频检测/分割 -> EdgeTAM初始化 -> 帧间掩膜传播
```

Grounding DINO保留为PC参考候选；当前没有确认其S100官方部署示例。若DOSOD无法转换为S100 HBM或端到端性能不合格，必须重新裁决S100已有参考链路的YOLOE等候选，不能把X5产物或PC可运行误写成S100 BPU已部署。

### 8.5 ROS 2数据链

```text
RGB + Depth + CameraInfo + TF
        -> 开放词汇provider
        -> 离散垃圾 / 地面脏污语义路由
        -> 时序跟踪与多帧确认
        -> RGB-D几何校验
        -> map坐标目标点或区域多边形
        -> ActionVerifier
        -> DynamicTrashMap / DirtyAreaMap
        -> 定点或区域加强清扫建议
```

- 离散物体使用掩膜内部有效深度的稳健统计估计三维位置，不直接使用检测框中心的单点深度。
- 落叶、灰尘和积水不能只发布一个中心点；应将有效掩膜投影到地面，形成地图坐标多边形或栅格面积。
- 非地面高度、深度跳变、有效深度不足、距离过远或跨帧位置不一致的结果不得确认。
- 模型置信度不能直接触发清扫，状态至少经过 `PROPOSAL -> TRACKED -> DEPTH_VALID -> CONFIRMED`。

### 8.6 运行频率与降级

- 重模型采用低频或事件触发运行，初始讨论范围为 `0.2–1 Hz`；S100轻量候选可从 `1–3 Hz` 开始评估。以上均不是性能承诺，必须按板端端到端实测冻结。
- 低频语义推理之间可使用CPU轻量跟踪或EdgeTAM维持目标，但结果超过时效必须失效。
- 模型超时、崩溃、低置信、深度无效或板端资源过载时，关闭定点/区域加强清扫和语义统计；定位、避障及全覆盖清扫继续运行。
- 不允许使用Gazebo semantic/instance真值进入控制链；真值只用于独立评测和合成数据标注。

### 8.7 零样本能力边界与验收

落叶堆通常具有较稳定纹理和边界，瓶、罐、纸等常见物体也可能受益于预训练开放词汇；但灰尘往往低对比、无稳定边界，积水又容易与阴影、反光和深色地面混淆。因明确禁止微调，不能预设这些类别会达到赛题精度。

正式选择模型前至少比较：

- 离散物体：逐类Precision、Recall、F1、背景误报率和三维定位误差。
- 区域脏污：逐类IoU、漏检面积、误报面积、地图投影误差和清后残留变化。
- 部署一致性：PC浮点结果与S100量化结果的检测框、分数和掩膜IoU一致性。
- 系统指标：端到端延迟、结果过期率、CPU/BPU/内存占用、温度和持续运行稳定性。

若所有S100零样本候选均未达到要求，本方案的降级终态是“全覆盖清扫继续、垃圾语义定点清扫关闭”，而不是违反约束进行微调或使用仿真真值控制。

### 8.8 硬件目标边界

本项目语境内RDK S100与征程6/Journey 6按用户决定视为同一车载计算平台，允许先在PC完成闭环demo，再逐模块迁移和验收。后续文档、模型产物和验收报告不再人为拆成两条互斥硬件链，但必须记录实际板卡SKU、系统镜像、工具链、BPU/CPU产物、模型哈希和实测性能；只有在真实板卡上运行的结果才能作为板端证据。

## 9. 障碍感知与动态行人测试方案

### 9.1 障碍处理原则

- LiDAR障碍感知独立于DOSOD + EdgeSAM垃圾/脏污感知。视觉语义模型失效不得导致避障能力丢失。
- 地图中的建筑、围墙、灯杆、垃圾桶、花坛等固定资产进入静态地图或静态代价层。
- 临时物品和行人进入局部障碍层；规划器不得把当前被占据区域当作可通行空间。
- 对会移动的目标不估计速度、方向或未来轨迹，也不进行行为预测。每次传感器更新都将其当前位置作为静态障碍物处理。
- 目标移动后，局部障碍层依据新观测更新；旧占据在满足清除条件后移除，局部规划器重新规划绕行路径。
- 如果当前没有安全绕行路径，车辆停车等待；不得因为目标被称为“动态行人”而沿预测方向抢行。
- 障碍层、车辆完整footprint、安全膨胀、Collision Monitor和紧急停车构成独立安全链。全局Coverage计划只决定待清扫区域和顺序，局部Nav2负责实时绕障。

这种方法不需要目标速度估计，工程复杂度较低；代价是对横穿、突然转向或长时间贴近车辆的行人会更保守，并可能反复停车和重规划。因此后续必须冻结障碍观测保持时间、清除时间、安全膨胀距离、停车距离和重规划频率。

### 9.2 感知与规划数据流

```text
静态场景资产 -> 保存地图 / 静态代价层 --------------------+
                                                       |
LiDAR当前扫描 -> 障碍点 -> 局部障碍层 -> 膨胀/碰撞检查 ----+-> Nav2局部重规划 -> 控制
                                                       |
Coverage计划 -> 当前清扫带 / 转场目标 ---------------------+

RGB-D -> DOSOD + EdgeSAM -> 垃圾/脏污目标 -> 定点或区域加强清扫
```

垃圾/脏污语义结果与安全障碍结果可以来自同一个相机视野，但在软件接口和故障处理上保持分离。行人是否被DOSOD正确命名，不影响LiDAR将其作为障碍物处理。

### 9.3 随机移动行人场景

- 基础世界保留固定的建筑、房屋、电线杆、路灯、垃圾桶、树木、花坛、围栏等静态资产。
- 每次正式测试依据独立随机种子生成若干移动行人；随机种子、行人数量、初始位置、目标点、路线和速度必须写入场景清单，确保失败可复现。
- 行人初始位置和运动路线不得与车辆、围墙或固定障碍重叠，也不得直接出生在不可达区域。
- 测试至少覆盖迎面接近、横穿清扫带、同向慢行、路口出现、窄通道占用和短时停止等情形，但控制链始终只使用其当前障碍位置，不读取仿真真值速度或未来路径。
- 行人真值轨迹只进入独立评测器，用于复算最小距离、碰撞和场景覆盖，不进入感知、规划或控制链。
- 随机行人不改变首次建图的静态正式地图；首次建图时观测到的人应作为临时障碍处理，不能固化为永久墙体。

### 9.4 障碍绕行验收

- 行人与车辆碰撞次数为零，固定设施碰撞次数为零，禁行区侵入为零。
- 报告车辆与行人的最小距离、停车次数、无路等待时间、局部重规划次数和任务完成时间。
- 行人离开后，车辆能够清除陈旧障碍并继续任务；行人持续阻塞时，车辆能够安全等待或将该区域延期，而不是无限振荡。
- 因绕障暂时遗漏的清扫区域进入补扫队列，最终覆盖率按清扫刷实际扫掠面积计算。
- 使用多随机种子评估，单次成功不作为稳定性结论。

## 10. 感知驱动的强化学习清扫规划方案

### 10.1 赛题边界与双模式设计

赛题功能要求包含“多场景全覆盖清扫”，创新评分中的算法优化则把“端到端 + 强化学习自动驾驶与避障”列为示例。使用强化学习本身不自动获得加分，必须通过基线对比证明技术收益。为避免按需清扫替换赛题硬功能，系统保留两个模式：

1. **全覆盖基线模式**：对全部可清扫区域执行覆盖规划，用于满足全覆盖功能、测量传统清扫效率，并作为强化学习方案的对照组。
2. **强化学习按需清扫模式**：刷盘只清扫已确认的垃圾或脏污区域；干净区域允许刷盘关闭，仅作为观察或转场路径。该模式用于展示感知驱动的主动搜索、任务排序和效率提升。

两种模式共用定位、DOSOD + EdgeSAM、Nav2、障碍层、Collision Monitor和车辆控制。强化学习不能绕过安全链，也不直接拥有转向、速度或刷盘的底层控制权。

本方案的内部核心约束是“有效观测区域不低于95%，且已观测区域内的地面脏污面积清除率和离散垃圾实例清除率均不低于95%”。剩余最多5%的未观测区域允许包含未发现、未清除的脏污，因此该指标不能表述为“全场真实脏污清除率不低于95%”。赛题原文中的95%主要对应垃圾/物体识别准确率和避障成功率，也不能与内部清扫指标混写。

### 10.2 问题定义：有限感知下的主动清扫

脏污位置在每个任务中随机生成，车辆只能看到相机当前有效视野内的地面，因此该问题不是“已知所有脏污坐标后的最短路”，而是部分可观测的主动搜索与清扫问题。

车辆可以不清扫干净区域，但为了发现未知脏污，仍需行驶到足够多的观察位置。感知距离越远、视场越宽、遮挡越少，观察路线越短；感知能力变弱时，策略应自然退化为接近全场观察遍历，而不能凭空判断未观察区域没有脏污。

策略维护多通道Belief Map：

- 静态占据与可通行区域；
- 当前LiDAR障碍层；
- 已观察地面及观测时间戳；
- 未观察区域；
- 脏污存在概率、类别、面积和置信度；
- 已确认脏污区域；
- 已清扫区域和清后复检结果；
- 当前任务预算、车辆位姿和停靠点方向。

只有真正落入相机有效地面视野、未被遮挡且达到可识别尺度的区域，才能记为“已观察”。一次没有检测到脏污只能降低对应可见区域的脏污概率，不能把整个相机量程内或建筑背后的区域标记为干净。

### 10.3 强化学习与传统规划的职责边界

强化学习策略低频选择高层动作并生成候选全局轨迹：

- 前往下一个已知脏污簇；
- 前往下一个观察视点或信息增益前沿；
- 延期当前被行人阻塞的目标；
- 等待；
- 返回固定停靠点；
- 在满足终止条件时结束任务。

策略输出目标区域、候选观察位姿及连接它们的全局参考轨迹，不直接输出方向盘、油门或制动。候选轨迹必须经过静态地图、实时障碍层、完整车辆footprint、Ackermann曲率和禁行区校验；Nav2可以接受、修正或拒绝该轨迹，并负责局部绕障与轨迹跟踪。实时LiDAR障碍层把移动行人按当前位置的静态障碍处理，控制器与Collision Monitor负责安全停车。强化学习不能通过输出轨迹绕过这些硬约束。

发现脏污后，确定性任务层根据掩膜生成清扫入口姿态和局部覆盖路径；策略只负责决定任务顺序，不用神经网络重新学习刷盘几何和局部清扫动作。

### 10.4 优化目标与奖励边界

采用约束优先或词典序目标，而不是用单个加权分数掩盖失败：

1. 对安全可达地面的有效观测面积比例 `>=95%`；
2. 已观测区域内的地面脏污实际扫过面积比例 `>=95%`；
3. 已观测区域内的离散垃圾实例清除率 `>=95%`；
4. 碰撞、越界和绕过安全链次数为零；
5. 在满足以上约束后最小化任务轨迹总长度，且不得超过相同场地、脏污和行人随机种子下的全覆盖基线轨迹长度。

训练奖励可包含实际清除的脏污量、首次发现奖励、Belief Map不确定性下降，并惩罚新增轨迹长度、无效行驶、重复观察、不可达目标和无收益提前结束。时间、能耗和等待时长不作为优化目标。仿真真值只允许用于奖励和独立评测，不能进入策略观测、DOSOD + EdgeSAM输出、Nav2代价地图或终止判断接口。

清扫率分母不能使用“模型检测到的脏污”；否则模型漏检会缩小分母并制造虚假的高分。建议默认定义为：

```text
有效观测面积比例 = 满足视距/FOV/遮挡/尺度条件的已观测可达地面面积 / 安全可达地面总面积
已观测地面脏污清除率 = 已观测区域内被刷盘真实扫过的初始脏污面积 / 已观测区域内初始脏污总面积
已观测离散垃圾清除率 = 已观测区域内被清除的初始离散垃圾实例数 / 已观测区域内初始离散垃圾实例总数
```

终止判断在实际运行中不能读取隐藏脏污真值。当Belief Map计算的有效观测面积比例达到95%，且所有已确认脏污均已执行一次有效清扫后，策略可以结束清扫任务。独立评测器再使用隐藏真值核算已观测区域内两类清除率及全场真实清除率；全场真实清除率只报告，不设95%硬门。

所有垃圾和脏污均按episode随机生成，且不参与首次静态建图。地面脏污按刷盘实际扫过的像素/面积逐步清除；未被刷盘覆盖的部分保持存在。离散垃圾只有在机械臂成功抓取、抬升、投入车后收纳箱并通过复核后才视为已清除，车辆或虚拟刷盘覆盖不能清除离散垃圾。当前方案不按地面脏污类别改变车速、清扫次数或刷盘参数。

### 10.5 随机任务生成

每个episode使用可复现且彼此独立的随机种子：

- `map_seed`：场地尺寸、建筑布局、开放区比例、窄通道、固定资产和遮挡关系；
- `dirt_seed`：垃圾/落叶/灰尘/积水的类别、数量、面积、位置、聚簇程度和可达性；
- `pedestrian_seed`：行人数量、出生点、路线、速度、停留和局部阻塞行为；
- `sensor_seed`：感知漏检/误检、深度误差、定位误差及传感器噪声。

每次运行保存四类种子、世界与配置哈希、模型/策略哈希和终态。随机脏污不得生成在建筑内部、车辆不可达区域或无法被任何合法观察位姿看到的位置，除非该episode明确用于不可达异常测试。

持续或暂时阻塞的行人不会直接把episode判为失败。策略可以等待、改道或延期相应观察/清扫区域；等待本身不增加轨迹长度。为防止仿真无限挂起，测试执行器仍需设置技术性的最大step/墙钟上限：达到上限的episode标记为“未完成/截断”，不能计作成功，也不能通过排除该样本提高统计成绩。

### 10.6 分阶段训练与跨场地泛化

1. **阶段A - 单场地闭环**：固定当前 `200 m × 100 m`园区，只随机脏污和行人，先验证观测、决策、Nav2执行、清扫和评分闭环。
2. **阶段B - 单拓扑域随机化**：保持主要拓扑，随机资产外观/位置扰动、脏污密度、行人密度、光照、材质和传感器噪声，降低策略记忆固定路线的可能。
3. **阶段C - 多场地训练**：程序化扩展多个场地，保持总面积不变，改变场地长宽比、边界形状、建筑布局、通道拓扑、开阔区比例、静态资产、地面材质、光照和遮挡，在训练集场地上继续训练。GNSS质量模型保持不变。
4. **阶段D - 未见场地验证**：在训练期间完全不可见的新场地、新脏污种子和新行人种子上冻结测试，验证策略是否真正泛化。

地图必须按 `map_seed` 划分训练、验证和最终测试集；不能只把同一张地图上的不同脏污种子称为“新场地”。测试场地跑差后若加入训练，该场地即不再是未见测试集，必须另建新的最终隐藏场地。

正式结果至少分开报告：

- 已见场地、未见脏污/行人任务；
- 同分布未见场地；
- 拓扑、尺度、材质或脏污分布变化的域外场地。

### 10.7 基线、消融与验收指标

至少使用相同场地和随机种子配对比较：

- 全场弓字形覆盖；
- Frontier观察 + 发现后就近清扫；
- 最近已知脏污贪心策略；
- 信息增益/预期脏污收益启发式；
- 预先知道全部脏污真值的Oracle路径上界；
- 强化学习策略。

消融至少包含：移除脏污语义、移除历史记忆、移除多场地训练、移除行人随机化、不同感知距离/FOV、不同漏检误检水平及不同奖励项。

每个episode首先判定观测面积、已观测脏污清除率和安全约束是否通过；只有满足硬约束后才比较轨迹长度。主效率指标为从任务启动到清扫完成终态的车辆实际轨迹总长度，并报告其相对全覆盖基线和Oracle上界的比例；时间、能耗和返航距离不进入主指标。辅助报告空驶距离、刷盘开启距离、全场真实清除率、碰撞、急停、等待、重规划和人工接管次数。只有清扫任务已经完成，车辆才开始返回固定停靠点。不得只展示最优episode或单个训练seed。

### 10.8 已冻结决策

1. 保留全覆盖基线模式和强化学习按需清扫模式。
2. 地面脏污按清除面积比例统计；离散垃圾按清除实例比例统计。
3. 地面脏污按刷盘实际扫过面积逐步清除；离散垃圾必须经机械臂抓取、抬升、投箱和复核后才视为清除。
4. 车辆允许在干净区域关闭刷盘通行，用于观察、转场和返航。
5. 相机安装高度、FOV、有效识别距离和推理频率使用最终真实设备参数，不使用为了提高仿真成绩而虚构的参数。
6. 强化学习是规划策略，可以输出全局参考轨迹，但底层控制和安全校验仍由确定性模块负责。
7. 泛化场地总面积保持不变，允许改变长宽比和边界形状；GNSS质量保持不变；布局、拓扑、资产、材质、光照、遮挡和脏污分布可以改变。
8. 返航不计入清扫效率；只有任务完成后才开始返航。
9. 垃圾和脏污在每个episode中随机产生，首次建图阶段忽略。
10. 有效观测面积达到95%后允许结束搜索，剩余5%区域中的脏污可以不发现、不清除。
11. 移动行人阻塞不直接判失败；优化只看实际任务轨迹长度，不看等待时间。
12. 最大任务轨迹长度不得超过相同随机任务的全覆盖基线轨迹长度；不设置时间和能耗优化预算。

### 10.9 训练、验证与最终测试预算

初版预算由项目侧冻结如下，后续只能在查看最终隐藏测试集之前按算力和收敛证据扩展：

- 阶段A固定场地：`10,000`个训练episode、`500`个验证episode、`1,000`个冻结测试episode。
- 多场地训练集：`32`个程序化场地，每个场地`200`组脏污/行人/sensor随机任务。
- 多场地验证集：`8`个独立场地，每个场地`100`组任务，用于选择checkpoint和超参数。
- 最终隐藏测试集：`12`个训练期间不可见场地，每个场地`100`组任务，只在策略与配置冻结后运行。
- 使用`5`个独立策略训练seed，报告均值、标准差、置信区间和最差尾部表现。
- 所有传统基线、Oracle和RL策略在验证/测试阶段使用完全相同的配对任务种子。

如果训练尚未收敛，只允许增加训练episode或训练场地，并保留原验证集；最终隐藏测试一旦开启，不得根据其结果继续训练或选择checkpoint。

具体强化学习算法暂不冻结。应先确定观测、动作、奖励、终止、数据划分和基线，再从适合候选目标或图节点选择的PPO、注意力策略或其他方法中做有界比较。

## 11. 真实小车缩比仿真与移动抓取方案

### 11.1 真实本体基准

后续Gazebo仿真改以用户提供的真实小车为本体基准，待URDF提供后冻结精确几何、关节、碰撞和传感器外参。当前已知配置为：

- 车体外形约 `0.60 m × 0.40 m`；
- 四个麦克纳姆全向轮；
- 一个单线LiDAR和一个Mid-360 LiDAR；
- 一个前向RGB-D相机；
- 两个侧后向鱼眼相机；
- 一个六轴机械臂；
- 机械臂末端为平行夹爪和双目相机。

原项目车辆约 `1.15 m × 0.72 m`。按车长得到比例 `0.60/1.15≈0.522`，按车宽得到比例 `0.40/0.72≈0.556`，两者不完全一致。在URDF到达前，方案暂用统一线性比例 `s=0.53`记录缩比关系；最终比例应由URDF的collision footprint、轴距、机械臂包络和真实清扫假设共同冻结。

若场地也按 `s=0.53`缩放，则原 `200 m × 100 m`场地约变为 `106 m × 53 m`，面积约 `5,618 m²`；原 `1.32 m`有效清扫宽度暂缩为约 `0.70 m`。该缩比场地不再满足原赛题 `20,000 m²`建图面积门，因此只定义为小车研发、闭环演示和迁移验证场，不能替代正式赛题场地；正式验收仍保留不小于 `20,000 m²`的场地配置。

### 11.2 底盘动力学与规划约束

真实物理底盘是麦克纳姆全向轮，但任务规划继续采用前轮转向/非完整运动约束：

- 仿真模型优先保留真实麦克纳姆轮、轮地接触、轮速和里程计特性；
- 规划轨迹强制满足 `v_y=0`、连续航向、有限曲率和最小转弯半径，不利用横移或原地旋转缩短成绩；
- 麦克纳姆底层控制器跟踪该受限轨迹，并单独报告轨迹跟踪误差；
- 安全footprint使用真实车体、收拢机械臂及突出传感器的完整包络，不能沿用原清洁车footprint。

该设计是在全向实车上人为施加保守的“虚拟Ackermann”任务约束。若Gazebo直接把小车伪装成真实前轮转向机构，轮滑、里程计和控制接口将与实车不一致，不能作为严格sim-to-real证据。

### 11.3 传感器职责与缩比

| 传感器 | 主要职责 |
|---|---|
| Mid-360 LiDAR | 三维环境障碍、局部代价地图和近车安全感知 |
| 单线LiDAR | 二维建图/定位基线和低高度障碍冗余 |
| 前向RGB-D | DOSOD + EdgeSAM垃圾/脏污发现、粗三维定位和地面投影 |
| 两个侧后鱼眼 | 周边可视化与补充态势感知；在无深度和标定证据前不作为定位或安全权威 |
| 末端双目 | 停车后的近距目标重定位、点云生成与抓取姿态输入 |

采用双profile：缩比研发profile按 `s`限制算法有效感知范围，用于快速闭环；真实传感器profile保留原始FOV、盲区、分辨率、标称量程和实测有效识别距离，用于sim-to-real验收。物理传感器本身的FOV、最小测距和噪声不会因任务缩比而改变，不能只用人为截短量程的缩比结果证明迁移成功。

若末端双目自身SDK不能直接输出标定深度，可评估D-Robotics官方[`hobot_stereonet`](https://github.com/D-Robotics/hobot_stereonet)的S100 ROS 2/BPU深度与点云链；若相机SDK已有稳定深度，应优先减少模型链。该组件只解决双目深度，不提供抓取姿态。

RL的感知范围使用DOSOD + EdgeSAM在真实相机参数下对3 cm目标实测得到的有效发现距离/概率，而不是LiDAR或相机的标称最大量程，也不是Gazebo理想可见圆。

### 11.4 无墙场地边界

场地四周不设置实体围墙。由于LiDAR无法从开放地面推断任务边界，首次建图和后续清扫均必须预先获得map/GNSS坐标系下的工作区geofence多边形：

- geofence只定义合法建图、观察和清扫范围，不提供内部障碍地图；
- frontier探索不能在geofence外生成目标；
- Nav2全局/局部代价地图、边界保护和Collision Monitor共同禁止越界；
- 场地长宽比或边界形状随机变化时，为每个 `map_seed`生成并记录对应geofence；
- 无墙不等于无边界，越过虚拟边界仍按安全违规处理。

### 11.5 垃圾与虚拟清扫对象

- 离散垃圾统一为边长 `3 cm`的立方体块，颜色按episode随机生成，并具有真实视觉、碰撞和可抓取几何。
- 地面脏污继续按随机掩膜/区域生成；车辆没有真实拖地盘，但仿真按缩比后的虚拟有效清扫宽度计算刷盘扫掠足迹。
- 地面脏污只有被虚拟刷盘实际覆盖的像素/面积才清除。
- 离散垃圾不能通过车辆覆盖清除，必须由机械臂成功抓取、抬离地面、完成投放并通过复核后才计为清除实例。
- 建图阶段继续忽略所有垃圾与脏污语义；离散块只可作为当前临时障碍，不能写入永久静态地图。
- 每个episode最多随机生成 `20`个立方体；全部单层放置、不堆叠，并与固定资产保留夹爪可进入的安全间距。每个目标还必须至少存在一个同时满足底盘安全停靠、机械臂可达和末端相机可见的抓取配置。
- 房屋、电线杆、垃圾桶、行人等外部资产保留真实尺寸，不随研发场地和车辆运动尺度缩小，以避免破坏实车感知迁移所需的目标尺度；随机位置仍必须满足碰撞和可达约束。

随机颜色的3 cm纯立方体并不具有天然的“垃圾”语义，DOSOD零样本检测未必稳定，且远距离像素尺寸可能很小。因此必须包含近地面同色、低对比和遮挡hard cases，并实测冻结提示词、有效发现距离和误检漏检；不能因为几何简单就预设检测通过。

### 11.6 抓取姿态方案选择

3 cm规则立方体不需要通用学习式6D抓取网络。主线改为可解释、易迁移的“RGB-D/双目深度几何 + 规则顶抓”：

1. 在前向RGB-D点云中裁剪地面工作区，分割地面平面；
2. 提取高出地面约 `3 cm`的点云，聚类并用OBB/立方体拟合筛选约 `30 mm`的紧凑目标；
3. DOSOD + EdgeSAM用于垃圾语义确认、目标掩膜和候选补充，但几何候选不得依赖Gazebo真值；
4. 停车后用末端双目近距重测目标中心、顶面法向和抓取高度；
5. 优先生成垂直顶抓。立方体绕竖直轴近似对称，夹爪yaw从少量候选中按IK余量和碰撞风险选择；
6. 使用MoveIt 2 Task Constructor或等价任务规划器执行预抓取、直线下降、闭爪、抬升和投箱。

[FineGrasp GraspNet-1B方案](https://github.com/HorizonRobotics/RoboOrchardLab/tree/master/projects/finegrasp_graspnet1b)只保留为PC/CUDA对照实验和后续复杂物体扩展候选。其官方示例输入对齐RGB、深度、相机内参、深度比例和工作空间，并在代码中把pipeline移到CUDA；当前官方目录未提供ROS 2、RDK S100 BPU或HBM部署。因此它不能作为最终S100单板闭环的默认依赖。

Contact-GraspNet、GraspGen等通用方法同样偏CUDA；GPD可走CPU点云路线，但对固定规则方块仍显著复杂。RDK S100官方已有LeRobot/ACT一类端到端策略部署流程，但它需要示教数据和训练，且不适合本项目当前“先闭环、抓取规则方块、不微调感知模型”的最小方案。只有在几何抓取对遮挡、堆叠或复杂物体失败且有量化证据时，才重新开启学习式抓取选型。

最终车载只有RDK S100，因此正式方案的全部在线控制链必须可在S100上运行；当前允许先在PC完成闭环demo。建议部署分工为：DOSOD + EdgeSAM走BPU，点云几何、TF、MoveIt 2和抓取状态机在ARM CPU运行。板端性能和兼容性属于后续硬门，在验证前不得声称已完成部署。

### 11.7 移动抓取流程

```text
前向RGB-D + DOSOD/EdgeSAM
        -> 深度点云地面分割、聚类、30 mm立方体拟合
        -> 语义/几何候选融合与TargetMap
        -> 生成机械臂可达的底盘预抓取位姿
        -> RL任务轨迹 / Nav2安全到位
        -> 底盘停车并锁定，机械臂从home展开
        -> 末端双目近距重观测与点云
        -> 生成垂直顶抓和少量夹爪yaw候选
        -> 可达性、地面、车体、机械臂和环境碰撞过滤
        -> MoveIt 2 Task Constructor执行预抓取、直线接近、闭爪、抬升、撤回
        -> 抓取结果验证
        -> 投放到车后收纳箱并再次验证
        -> 更新离散垃圾实例清除状态
```

- 底盘行驶时机械臂必须回到home/运输姿态；机械臂执行时底盘保持静止。
- 候选抓取姿态不能直接下发关节；必须先进行IK、关节限位和全场景碰撞检查。
- 若行人进入机械臂安全区，机械臂暂停或安全回撤；垃圾感知和导航安全链保持独立。
- 抓取验证至少组合夹爪开度/力矩、目标是否随末端抬升、原位置候选是否消失中的两项真实可迁移证据。Gazebo接触或attach状态只能用于调试和评分真值，不能进入控制链。
- 同一实例最多执行两次抓取尝试；耗尽后保持未清除并计入最终离散垃圾清除率，任务继续。
- 车后固定设置 `0.20 m × 0.20 m × 0.10 m`收纳箱。箱体和开口必须进入URDF/规划场景的碰撞模型；投放采用箱口中央上方的固定预投放位。理论规则堆放最多为 `6 × 6 × 3 = 108`块，但随机落箱的安全容量必须由仿真统计后冻结，不能使用理论容量作为可用容量。
- 抓取和底盘对位产生的车辆轨迹属于清扫任务轨迹；收纳箱随车，因此没有单独前往固定投放点的车辆里程。任务完成后的返航仍不计入主效率。

### 11.8 已冻结决策与剩余接口

已冻结：缩比场只用于研发/迁移；Gazebo保留真实麦克纳姆动力学并施加虚拟Ackermann规划约束；无墙场地预先提供geofence；采用缩比/真实双感知profile；使用车后 `20 cm × 20 cm × 10 cm`收纳箱；最终在线链必须部署在RDK S100但先做PC闭环；允许RGB-D几何补充DOSOD且禁止真值控制；外部资产保留真实尺寸；每个目标最多抓取两次。

以下接口待URDF、标定或任务生成器到达后冻结，不阻碍当前方案记录：

1. 虚拟清扫宽度暂记 `0.70 m`，最终按URDF footprint和清扫比例确认；
2. 机械臂关节、工作空间、额定载荷、安装位姿及后箱可达性；
3. 夹爪开度、指宽、闭合反馈和允许夹持力；
4. 末端双目基线、内外参、最近工作距离，以及是否直接提供标定后的深度/点云；
5. 每个episode最多生成 `20`个方块，必须小于实测安全箱容量；箱满后的卸载行为当前不纳入任务；
6. 主效率指标继续只统计底盘轨迹总长度，机械臂轨迹、抓取次数和耗时作为辅助诊断指标；
7. 方块冻结为单层、不堆叠，并与固定障碍保留夹爪可进入的间距；若以后加入堆叠/紧贴障碍，需单独升级抓取策略；
8. 抓取时底盘完全停止；行人进入机械臂安全区时暂停或回撤，安全后重新规划或延期该目标。

## 12. 当前边界

在真实URDF到达前已经完成：

- 生成 `106 m × 53 m`研发场和 `200 m × 100 m`正式场；52张地图保持总面积不变并改变长宽比，冻结32/8/12地图和6,400/800/1,200任务索引。园区无实体外墙，包含真实尺度建筑、杆、垃圾桶、树、长椅、随机地污、20个单层3 cm方块及8个移动行人。
- 场景输出分为controller可见的`public`、环境驱动专用的`environment`和评测专用的`evaluator`；hidden public清单不含种子、真值或行人计划。Gazebo Harmonic已验证SDF、代理底盘、8个行人实体、`set_pose`服务和行人实际移动。
- 完成URDF无关主动清扫环境、全覆盖/感知贪心/Oracle基线、belief-only Q-learning、实际扫掠面积、95%终止/评分、虚拟Ackermann轨迹、安全碰撞审计、角色独立随机种子和配对评测。
- 完成参数化占位Xacro/SRDF、3 cm方块几何检测/顶抓、最多两次尝试、两类独立抓取验证、20件后箱、单目标主动清扫适配和投箱后才清除的fail-closed状态机。
- 完成DOSOD + EdgeSAM的PC/S100运行契约和真值拒绝边界；EdgeSAM记录为官方S100支持，DOSOD的S100移植仍未验证，缺少模型产物时必须保持not-ready。
- 统一演示在研发场单任务达到观测率`97.43%`、已观测地污清除率`100%`、离散垃圾清除率`95%`，19个目标均由占位投箱回调验证，任务轨迹`413.38 m`，碰撞/越界/非法动作为0。该结果只证明软件语义闭环。

仍必须等待真实URDF或外部资源后完成：

- 实测底盘/机械臂/夹爪/后箱几何、惯量、关节限位、外参和标定，以及Gazebo传感器、`ros2_control`、MoveIt 2、IK、自碰撞、可达性和真实夹持反馈。
- 将单线LiDAR、MID-360、RGB-D、鱼眼、轮速、GNSS接入新园区的SLAM、固图、定位、Nav2和安全链，并完成首次建图到后续任务的真实闭环。
- 下载并锁定DOSOD/EdgeSAM权重和源码版本，完成真实相机输入的PC推理；随后解决DOSOD的S100移植、量化、板端运行和性能验收。
- 运行阶段A的10,000/500/1,000预算及多场地6,400/800/1,200冻结任务，报告全量统计、失败样本和泛化结果；当前只生成了预算索引并完成少量确定性训练/演示。
- 用真实感知结果替换统一演示中的belief传感模拟、圆形地污栅格近似和合成近距方块几何，并在正式`200 m × 100 m`场地重复Gazebo综合验收。
- 按[高保真竞赛清扫车虚拟样机规划](high-fidelity-competition-vehicle-plan.md)完成A300条件准入、四张预算表、完整CAD/Xacro、显式电机/刷盘/刮吸机构、积水体积守恒、污水箱和垃圾箱动态质量、UR5e + 2F-85移动抓取及征程6/S100部署。A300当前只是条件候选，尚未最终冻结。

因此，本阶段不对真实建图定位、零样本感知精度、机械臂可达性、RDK S100性能、正式泛化成绩或实车迁移作通过声明。

## 13. 正式高保真整车分支

此前 `0.60 m × 0.40 m`麦克纳姆小车和通用六轴臂继续作为URDF无关研发profile，用于保持环境、规划、感知、抓取和评分接口可运行；它不再承担正式竞赛整车的尺寸、载荷、清扫机构和积水回收真实性。

正式profile改为条件候选Husky A300、UTM-30LX、MID-360、前向RGB-D、两个侧后鱼眼、末端相机、UR5e、Robotiq 2F-85、征程6/S100、`45 L`干垃圾箱和显式刷盘/刮吸/污水箱总成。积水只有在受真实泵流量限制的情况下从地面水层扣除、等量进入污水箱并增加整车质量，才算回收；3 cm垃圾按纸板、PP、PET、铝材料随机质量生成，投箱后保留为箱内刚体并改变总质量和重心。

完整BOM、动力学分层、流量公式、质量预算、阶段门、工作量和三项待确认输入见[高保真竞赛清扫车虚拟样机规划与可行性评估](high-fidelity-competition-vehicle-plan.md)。该文档是规划，不是已实现能力或通过证据。
