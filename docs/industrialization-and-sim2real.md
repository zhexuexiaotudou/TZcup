# 工业化交付与 Sim-to-Real 准入

## 当前可交付边界

独立小场地用于快速开发和功能演示，真实执行链仍是 Gazebo → 混合定位 → Nav2 →
Coverage → 车辆与刷盘。右侧实时作业地图的面积和目标统计使用 Gazebo 真值与刷盘足迹；
目标达到判定半径后从演示场景移除以直观表达结果。它只用于仿真评估，不等价于实车垃圾
识别、吸入确认或称重结果。

当前已经工程化解决的部分包括：接口单位与坐标系冻结、命令和传感器频率/超时、急停和
失联失效安全约束、SIL/HIL/场测三级门槛、启动前契约校验，以及传输压力、湿滑路面和
执行器衰减故障档案。对应真值文件是：

- `starter_ws/src/sanitation_tasks/config/hardware_interface_contract.yaml`
- `starter_ws/src/sanitation_tasks/config/sim2real_fault_profiles.yaml`
- `scripts/validate_hardware_interface_contract.py`

每次视觉仿真启动时会生成 `hardware_interface_contract_validation.json`；校验失败则不启动。

## 从仿真推到实车的主要风险

| 风险 | 已有防线 | 进入实车前必须补齐的证据 |
|---|---|---|
| 轮胎打滑、载荷和胎压变化 | 湿滑/驱动衰减参数档案，速度和加速度上限 | 不同路面实测里程计标定、制动距离和横摆误差 |
| 传感器延迟、丢包、时钟漂移 | 频率、新鲜度和 20 ms 时钟偏差契约 | PTP/NTP 状态、72 h 数据丢包与时间同步记录 |
| 雷达/相机安装偏差 | `map/base_link` 和 SI 单位冻结 | 外参标定报告、热循环与振动后复标 |
| 仿真目标与真实垃圾域差异 | 仿真目标统计明确标记为 evaluation-only | 真实道路数据集、逐类精确率/召回率和吸入确认传感器 |
| 刷盘/风机迟滞、堵塞和磨损 | 刷盘命令超时与 0.5 s 停止约束 | 电流/转速反馈、堵塞诊断、磨损补偿与称重闭环 |
| ROS 进程或通信失效 | 命令/定位超时 fail-safe | 独立硬件急停链、驱动器 watchdog 和断网停车验收 |
| 算力热降频和资源竞争 | 2x/3x 仅作为开发档位，不改变生产约束 | 目标计算平台满载温升、P99 延迟、内存和磁盘耐久测试 |
| 地图变化与定位发散 | 融合定位和误差门槛 | 施工、积水、遮挡、GNSS 拒止场景回放与现场降级策略 |
| 软件升级失败 | 契约版本与回滚包要求 | A/B 或原子升级、签名校验、断电恢复和回滚演练 |

## 准入顺序

1. SIL：四个故障档案全部运行，碰撞为零，覆盖率不低于 90%，定位 P95 不高于 0.20 m。
2. HIL：接入真实控制器、传感器时间戳和硬件急停，验证命令 P95 延迟与停车链。
3. 封闭场：先无刷盘、后低速刷盘，再做湿滑和动态障碍；任何失效必须落入停车状态。
4. 真实道路：至少连续 20 次安全任务、零人工接管，保留 MCAP、事件日志和版本清单。
5. 量产：设备身份、最小权限、签名升级、远程诊断、备件和维护周期全部纳入发布清单。

在 HIL 和封闭场证据完成前，项目只能标记为“仿真功能链可演示”，不能标记为实车或工业
产品已验收。
