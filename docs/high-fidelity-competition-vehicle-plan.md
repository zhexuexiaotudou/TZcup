# 高保真竞赛清扫车虚拟样机规划与可行性评估

> 状态：方案冻结稿V2，2026-08-25。配套[URDF实施前准备包](pre-urdf-readiness.md)已冻结来源、型号、接口和预预算；尚未制作正式CAD/URDF、编写插件或运行高保真整车仿真。
>
> 适用对象：正式 `>=20,000 m²` 竞赛级虚拟样机。既有 `0.60 m × 0.40 m` 小车占位profile继续用于协议和算法研发，但不再作为最终整车尺寸或载荷依据。

## 1. 本轮冻结的用户决策

1. 允许选用开源 Husky A300 作为底盘，但只有在满足既定技术方案、赛题效率、载荷、重心、供电和安全门后才正式冻结；任何一项失败即重新选型。
2. 积水必须经刷盘、刮水胶条和负压/水泵链路真正回收到污水箱。仅把积水贴图隐藏、将掩膜置零或用评测器直接删除，不计为清洁成功。
3. 离散垃圾仍为边长 `3 cm` 的立方体；每个episode按纸板、PP、PET、铝四类材料随机赋予质量，并作为真实刚体被夹取、运输和投入垃圾箱。
4. 项目语境内 `S100` 与 `征程6/Journey 6` 指同一车载计算平台，不再建立两条互相排斥的硬件证据链。具体芯片SKU、系统镜像、工具链和模型产物仍须在板端验收时记录。
5. 所有复杂机构均展开为可见、可碰撞、带惯量和运动约束的部件；“一个固定方盒代表机械臂/电机/刷盘/水泵”的符号化模型不进入正式profile。
6. 对没有完整第三方开放URDF的刷盘、刮吸、泵、箱体和支架，允许依据真实公开数据表自行建立并开源CAD/Xacro；来源、尺寸、参数、许可证和文件哈希必须可追溯。
7. 赛题明确要求的是 `40 L`尘箱，未规定污水箱容积，也未要求粒子/CFD级积水仿真。正式方案保守地保证干垃圾舱可用容积 `>=40 L`，污水舱在不超载前提下另行反算；积水主仿真采用简化但质量守恒的模型。

## 2. 设计目标与真实性分级

“无限接近现实”拆为四个可以验收的层级，避免把外观精细误当作物理真实：

| 层级 | 必须具备 | 不允许的替代 |
|---|---|---|
| 几何与装配 | 真实型号尺寸、安装孔位、传感器遮挡、完整运动包络、视觉和碰撞网格 | 只摆放外壳图片或无碰撞mesh |
| 刚体与执行器 | 每个运动部件的质量、惯量、关节限位、摩擦、阻尼、传动比、扭矩-转速和控制延迟 | 只在URDF写一个continuous joint便宣称电机完成 |
| 任务物理 | 轮地接触、刷盘接触包络、垃圾刚体、投箱后载荷变化、积水体积/质量守恒、泵流量和箱容积 | 碰到即删除、无质量变化、无限泵流量 |
| 传感与软件 | 真实FOV/盲区/频率/噪声/外参，ROS 2控制、MoveIt 2、Nav2、故障和超时链 | Gazebo真值进入控制链 |

正式交付称为“高保真名义数字样机”，不是经过实物标定的数字孪生。由于除征程6外不购买实物，制造公差、实际线束柔性、轮胎磨损、刷毛老化、泵效率衰减和单台传感器标定误差只能按公开资料的容差分布模拟，不能声称已与某台实车逐项校准。

### 3.1 赛题对箱体和积水的实际要求

项目赛题映射和总提示词明确写明 `40 L`尘箱、轻度积水深度 `<=1 cm`、清洁宽度 `>=600 mm`、清扫效率 `>=3500 m²/h`。其中积水在现有仿真评测中被定义为“低摩擦薄层区域和速度限制”，证据是通过率、横向误差和打滑率代理量；文件同时明确“实际积水清洁效果”不能由初期短时仿真直接证明。没有找到以下要求：

- 污水箱必须达到某个指定容积；
- 尘箱容积允许由干垃圾和污水共享；
- Gazebo必须模拟水滴、自由液面、软管内部流动或CFD；
- `3500 m²/h`必须在连续 `1 cm`深积水上保持。

因此采用保守口径：`40 L`只记为干垃圾舱的最低可用容积，污水舱是额外舱室；常规清扫效率按赛题口径验收，积水区允许按真实回收能力局部降速并独立报告。若后续获得更权威的赛题原文或裁判解释，优先更新本节而不是修改历史证据。

## 4. A300条件准入评估

Clearpath公开规格给出的40 Ah A300关键边界为：`990 mm × 698 mm × 372 mm`、本体 `78.5 kg`、平坦地面宽转弯可用载荷 `101.5 kg`、最高 `2 m/s`、平均运行时间 `8 h`、用户电源含 `12 V/10 A`、`24 V/5 A`和大电流VBAT。该平均续航是在特定占空条件下得到，不能直接代表加载机械臂、刷盘和负压风机后的整场续航。

### 4.1 准入门

A300只有同时满足以下条件才冻结：

1. 场地以平整硬地面为主，正式路线不要求跨越路沿；侧刷可以沿路沿边缘作业，但底盘不把攀爬路沿作为清扫动作。
2. 满载时总附加载荷不超过 `101.5 kg`，且保留不少于 `10%` 的工程裕量，建议设计上限 `<=91 kg`。
3. 任意垃圾分布、机械臂运输姿态和污水箱液位下，组合重心仍位于A300允许稳定锥内；急停、转弯和坡度工况分别验证。
4. 清扫、泵、机械臂、传感器和征程6的持续/峰值电流不超过各电源支路、线束、保险和电池能力。
5. 常规清扫profile在包含掉头、重叠、避障和补扫后仍达到赛题 `>=3500 m²/h`；不得只用 `宽度×最高车速` 理论值通过。
6. 完整车体、刷盘、机械臂和传感器包络可通过计划中的最窄通道，并保持急停按钮和维护口不被遮挡。

### 4.2 初始质量预算

| 项目 | 当前可确认/规划值 | 说明 |
|---|---:|---|
| UR5e机械臂 | `20.7 kg` | 官方整臂质量 |
| UR控制箱 | 约 `12 kg` | 若正式样机保留标准控制箱；OEM控制器需另行取证 |
| 2F-85夹爪 | 约 `0.925 kg` | 不含末端转接板/相机 |
| 满箱20个垃圾块 | `0.16–1.51 kg`量级 | 取决于随机材料，铝制实心块最重 |
| 污水 | `1 kg/L` | 容量每增加 `1 L`就增加约 `1 kg`满载质量，是主要动态载荷 |
| 其余 | 待实算 | 刷盘、升降、刮吸、泵、箱体、传感器、征程6、线束和支架 |

因此40 Ah A300从“尺寸和名义载荷”看有希望，但不是已经通过。若污水舱设为 `40 L`，仅机械臂、标准控制箱、夹爪和满舱水已约 `73.6 kg`，留给全部清扫机构、干垃圾舱、传感器、计算、支架和线束的设计质量不足 `18 kg`（按10%裕量），风险很高。污水舱不再预先固定为20 L，而是按以下顺序反算：

```text
m_payload_design = 0.90 * 101.5 kg = 91.35 kg
m_water_by_mass = m_payload_design - m_fixed_payload - m_dry_trash_max
V_water_by_mass = max(0, m_water_by_mass / rho_water)
V_wet_nominal = min(V_water_by_mass, V_water_by_CoG, V_install_space, 20 L)
V_wet_usable = 0.80 * V_wet_nominal
V_puddle_episode_max = 0.875 * V_wet_usable
```

`m_fixed_payload`包含机械臂、控制器、夹爪、空干/湿舱、清扫回收机构、全部传感器、征程6、线束和支架；`m_dry_trash_max`按本任务20个随机材料方块的最坏质量计算。`V_water_by_CoG`来自液位和机械臂各姿态的稳定性扫描。正常episode只生成不超过`V_puddle_episode_max`的初始积水；满舱/溢出另作负向工况，不能混入正常成功率。这样既保证干垃圾舱始终 `>=40 L`，也不会用一个任意水箱容积推高载荷。

## 5. 底盘、规划和传感器高保真建模

### 5.1 底盘与规划不冲突的处理

- 物理模型保留A300四轮独立电机和滑移转向，包含轮胎摩擦、侧滑、轮径误差、驱动电机扭矩-转速、限流和制动延迟。
- 任务规划继续执行此前冻结的“虚拟Ackermann”约束：禁止横移，限制曲率、曲率变化率和最小转弯半径，计分任务不利用原地转向缩短轨迹。
- 控制层把该轨迹转换为左右轮速；真实滑移导致的跟踪误差进入定位和覆盖评测，不能用理想轨迹替代实车位姿。
- 安全footprint按机械臂收拢、侧刷伸出/收回、刮吸组件和传感器的状态动态切换。

### 5.2 传感器安装冻结流程

每个传感器先依据真实外形和接口建立mount候选，再通过以下联合优化冻结位置：

1. 检查车体、机械臂、垃圾箱和清扫机构对FOV的遮挡；
2. 检查MID-360、UTM-30LX、RGB-D和鱼眼的盲区拼接；
3. 检查抓取、投箱、机械臂运输姿态和急停时的自遮挡；
4. 检查线缆弯曲半径、支架刚度和维护可达性；
5. 输出精确 `base_link -> sensor_link` 外参、CAD图、TF和Gazebo sensor参数；
6. 用射线覆盖图报告地面有效观察范围，不用标称量程替代DOSOD + EdgeSAM对3 cm目标的实测发现范围。

正式profile不在方案阶段凭空给出安装坐标。坐标必须由整车布局、机械臂包络和清扫总成CAD共同求解后冻结。

## 6. 清扫、刷盘和电机模型

### 6.1 显式机构

正式模型至少包含：左右侧刷刷盘、刷毛扇区、刷轴、轴承座、减速机、无刷/直流电机定子和转子、联轴器、防护罩、中央滚刷或洗地刷、升降连杆/推杆、后置刮水胶条、浮动支架、吸口、软管、过滤/气液分离、风机/水泵、污水箱、液位传感器和安装紧固件。

URDF/Xacro负责树形装配、几何、质量、惯量和关节；`ros2_control + gz_ros2_control`负责命令/状态接口；自定义Gazebo系统插件负责电机传动、低通响应、扭矩-转速、限流、堵转、热状态和非线性浮动连杆。公开的 `gz_ros2_control`接口支持为复杂机构和执行器动态编写自定义模拟插件，因此不需要把所有动力学伪装成理想关节。

### 6.2 刷毛建模分层

- 整场主仿真：每个刷盘使用 `12–24` 个有顺应性和接触参数的刷毛扇区，计算接触压力、扫掠速度和有效覆盖；不能把数千根刷毛全部建成独立刚体，否则20,000 m²场景无法实时运行。
- 机构微型验证场：对单个刷盘、单块垃圾和小片积水使用更细刷毛/接触粒度，标定主模型的等效摩擦、汇聚和刮吸参数。
- 外观层可以显示更密集的非碰撞刷毛，但评测只读取物理扇区和接触模型。

电机验收至少覆盖空载、额定负载、堵转、升降、刷盘触地/离地、紧急停机和恢复；记录转速、扭矩、电流、温度代理量和响应时间。

## 7. 积水真实回收模型

### 7.1 赛题要求与三档精度

赛题只要求 `<=1 cm`轻度积水工况；现有正式证据口径是低摩擦区内的通过率、横向误差和打滑代理量，并明确实际清洁效果仍需实车补齐。因此冻结三个互不冒充的精度档：

| 档位 | 用途 | 实现边界 | 状态 |
|---|---|---|---|
| L0 赛题回归 | 验证湿滑地面导航和控制 | `<=1 cm`可视水斑、低摩擦材质、速度限制，不声明回收 | 保留，与历史S06一致 |
| L1 主闭环 | 满足用户要求的“水真正进入污水舱” | 精确机构 + 稀疏2.5D水层 + 有界回收率/流量 + 污水舱动态质量 | 首版正式实现 |
| L2 微型高精度 | 后续标定刮水和水体趋势 | 小场有限粒子、细刷毛或外部CFD/多体对照 | 时间允许后增强，不阻断首版 |

Gazebo Classic的SPH流体教程已标为过时且实验性，直接在20,000 m²场景为全部水生成粒子不具备工程可运行性。L1主场采用只在积水区域分配的稀疏栅格/多边形连续水层，仍然满足回收闭环的关键约束：

- 每个水单元保存面积、液层厚度、体积和质量，水密度按 `1000 kg/m³`；
- 刷盘接触只改变水的空间分布和汇聚效率，不直接消灭水；
- 后刮水胶条接触包络把水导向吸口，回收量受胶条接触、车辆速度、吸口宽度和瞬时可用水量限制；
- 首版泵/风机用数据表额定流量、功率和一个有界分段效率模型给出最大回收量，不能无限吸取；暂不求解叶轮、软管内部两相流或完整压力场；
- 实际回收体积从地面单元扣除，并等量增加污水箱液位和质量；泄漏、残留和回收效率显式记录；
- 污水箱达到高液位时停止吸水并使任务保持未完成，不能溢出后仍计为成功。

L1暂不模拟水滴飞溅、自由液面波纹、毛细作用、刷毛逐根携水、泡沫、软管内部流动和真实污水黏度变化。独立L2小型流体场可使用有限粒子或更高精度CFD/多体工具验证刮水趋势，但它只用于后续标定和可视化，不替代主场体积守恒评分。

### 7.2 流量与速度硬约束

车辆通过近似矩形积水时，理想瞬时回收流量下界为：

```text
Q_required = h * w_wet * v
```

其中 `h` 为水深、`w_wet`为有效刮吸宽度、`v`为车速。换算为升每秒需再乘 `1000`。例如 `h=0.01 m`、`w_wet=0.80 m`、`v=0.10 m/s` 时，理想值已达 `0.8 L/s = 48 L/min`，还未计泄漏和效率损失。因此：

1. `<=1 cm`是允许的最深轻度积水边界，不应被理解为全宽连续铺满且仍以高速通过；
2. 常规干扫/地污模式仍按赛题 `>=3500 m²/h`验收；发现积水后切换局部低速刮吸profile，赛题没有要求该局部工况独立达到3500；
3. 积水生成器必须同时限制面积、深度和总容积，且总可回收体积不超过污水箱可用容积；
4. 正式报告分开给出常规清扫面积效率与局部积水回收率、回收体积、残留深度和湿区附加里程；
5. 若赛题要求“在1 cm满宽积水上仍保持3500 m²/h”，现有A300级清扫总成在物理上极不现实，必须另选工业大流量设备或重新解释指标。

L1内部工程门冻结为：可达积水回收体积比例 `>=95%`、任务终态无箱体溢出、地面扣减质量与污水舱增重误差 `<=1%`、刷盘/刮条/回收机未同时满足条件时回收量必须为零。前两项是本项目额外闭环指标，不冒充赛题原文明确分值。

## 8. 垃圾材料、质量和垃圾箱动态载荷

### 8.1 质量生成

单个方块体积固定为：

```text
V = 0.03^3 = 2.7e-5 m³
m = rho * V
```

初始建议把方块定义为均质实心试样，并按episode从下表分布采样；每次运行保存 `material_id`、密度、质量、摩擦、恢复系数和随机种子：

| 材料 | 建议密度采样范围 | 对应单块质量 |
|---|---:|---:|
| 纸板/硬纸板 | `300–700 kg/m³` | `8.1–18.9 g` |
| PP | `890–920 kg/m³` | `24.0–24.8 g` |
| PET | `1330–1450 kg/m³` | `35.9–39.2 g` |
| 铝 | `2600–2800 kg/m³` | `70.2–75.6 g` |

这些范围是方案初值，实施前须用许可可引用的材料数据表冻结。若用户希望模拟“空心包装垃圾”而不是实心材料试块，则增加壁厚/填充率分布；不能一边使用实心密度，一边把结果称为真实空瓶质量。

### 8.2 投箱后的真实质量变化

- 方块从生成到最终卸载始终是同一个刚体，不在投箱后删除或变成零质量计数器。
- 垃圾进入几何约45 L、可用容积不少于40 L的干垃圾舱后，通过真实接触、摩擦和重力在舱内落下；整车总质量和组合重心由物理引擎自然改变。污水进入相邻水密舱，不与干垃圾刚体混合。
- 为避免长任务内无意义的高频弹跳，可在方块稳定接触箱底/已有垃圾并满足速度阈值后进入sleep；若采用固定关节稳定，必须保留原质量和惯量并更新到正确位置。
- 每次抓取后核对 `箱内质量增量 ≈ 方块质量`、方块实体仍在箱内、原地不存在同一实体；三项不一致时不得计为清除。
- 20块全为铝时总质量约 `1.4–1.5 kg`，对A300载荷影响小于污水，但仍进入重心、制动和机械臂负载计算。

## 9. 移动抓取与机械臂高保真链

主方案保持“RGB-D/双目几何 + 规则顶抓”，不为规则3 cm立方体引入不必要的通用学习抓取网络：

1. 前向RGB-D和DOSOD + EdgeSAM建立目标候选，深度几何确认尺寸、顶面和地图位置；
2. Nav2把A300移动到UR5e可达且不遮挡的预抓取位，底盘制动并锁定；
3. UR5e从运输姿态展开，末端相机近距复测；
4. MoveIt 2 Task Constructor执行IK、全场碰撞、自碰撞、预抓取、直线下降、2F-85闭合、抬升和撤回；
5. 用夹爪开度/电流代理、目标随末端运动、原位置目标消失中的至少两项在线证据确认抓取；
6. 机械臂到后置箱预投放位，打开夹爪；只有方块实体进入箱内且质量增量正确才确认清除；
7. 机械臂回运输姿态后底盘才恢复行驶。

UR5e/2F-85使用官方或厂商维护的开放ROS 2描述和真实关节限位；安装底座、相机支架、后箱和清扫机构则由项目自建。FineGrasp继续只作为复杂垃圾扩展对照，不进入规则方块主线。

## 10. 效率、功率和容量联合验收

### 10.1 常规清扫效率

理论面积效率为：

```text
A_theory = w_clean * v * 3600
A_effective = A_theory * eta_route
```

仓库AUTO-12已有 `1.32 m`名义工作宽度、`1.0 m/s`离线轨迹约 `4205.81 m²/h` 的证据，可作为几何起点，但不是新整车通过证据。新车必须用真实刷盘/刮吸包络、A300滑移、机械臂停靠、随机行人和补扫重新测量。建议：

- 常规清扫保持 `1.32 m`级侧刷总工作宽度，主行驶速度从 `1.0 m/s`开始；
- 湿区刮吸宽度可以小于干扫宽度，进入湿区后按泵流量降速；
- 赛题 `>=3500 m²/h`在常规全覆盖profile单独设硬门；湿区额外报告整体任务效率及局部回收性能，不隐藏速度损失。

### 10.2 联合预算门

在冻结任何URDF前先生成四张可机器校验的账表：

1. `mass_budget.csv`：空载、最大垃圾、最大污水和机械臂各姿态的质量/重心；
2. `power_budget.csv`：持续、典型和峰值功率，电压、支路、转换效率、保险和线束；
3. `capacity_budget.csv`：干垃圾舱几何/可用容积、污水舱名义/可用容积、随机任务最大垃圾/积水量和正常/溢出工况；
4. `throughput_budget.csv`：清扫宽度、速度、路线效率、泵流量、湿区速度和全任务面积效率。

缺少任一账表，A300不得从“候选”提升为“冻结底盘”。

## 11. 分阶段实施顺序与验收门

### Phase 0：来源、许可证和参数冻结

- 锁定A300、UR5e、2F-85、UTM-30LX、MID-360、D435、GNSS、IMU、鱼眼、电机、减速机、泵/风机的源仓库revision、许可证、数据表和哈希。
- 完成质量、重心、功率、容量和吞吐四张账表。
- Gate：A300条件准入全部通过；否则返回底盘/清扫总成选型。

### Phase 1：整车装配与传感器覆盖

- 集成A300开放描述，设计承载框架、机械臂座、同柜水密分隔的 `>=40 L`可用干舱和载荷反算污水舱、传感器桅杆和维护空间。
- 生成传感器FOV、盲区、自遮挡、机械臂包络和完整footprint报告。
- Gate：几何无穿模、质量/惯量完整、维护和急停区域可达。

### Phase 2：底盘、执行器与清扫机构

- 完成四轮动力学、各刷盘/滚刷/升降/刮吸部件、每个电机和传动的URDF/Xacro与控制插件。
- 在机构微型场标定接触、扭矩-转速、堵转、浮动和急停。
- Gate：没有理想瞬时执行器，命令/状态/故障可观察。

### Phase 3：垃圾和污水动态载荷

- 实现材料随机化、刚体抓取/投箱、箱内增重和重心变化。
- 实现地面水层、刮吸、泵曲线、污水箱液位和质量守恒。
- Gate：垃圾与水的质量误差均 `<=1%`，满载制动/转弯/稳定性通过。

### Phase 4：定位、导航和移动抓取

- 接入2D/3D LiDAR、GNSS、IMU、轮速、RGB-D和鱼眼；完成首次建图、固图、重定位、Nav2和Collision Monitor。
- 完成UR5e + 2F-85的MoveIt 2规划、停车抓取、投箱复核和安全回撤。
- Gate：不用Gazebo真值完成定位、避障和20块随机材料垃圾闭环。

### Phase 5：正式场与策略验收

- 在 `>=20,000 m²`场运行全覆盖和RL按需清扫双模式；随机脏污、积水、垃圾材料和行人。
- 分开报告常规面积效率、湿区回收、总轨迹、95%观察/清除、安全、箱容量和能耗。
- Gate：所有赛题硬指标、多seed和未见场地统计通过。

### Phase 6：征程6/S100部署

- 先冻结PC闭环，再迁移DOSOD + EdgeSAM、几何处理、Nav2/MoveIt 2接口和监控链。
- 记录真实板卡SKU、系统、BPU/CPU产物、延迟、资源、温度、功耗和持续运行。
- Gate：板端实际结果通过；PC结果不能冒充板端证据。

## 12. 可行性与工作量结论

### 12.1 分项结论

| 项目 | 可行性 | 说明 |
|---|---|---|
| 开源底盘、机械臂、夹爪和主要传感器组合 | 高 | 有可用ROS 2描述和公开规格，集成工作明确 |
| 每个刚性部件、关节和电机显式建模 | 高 | URDF/Xacro + ros2_control + Gazebo插件可实现 |
| 垃圾材料随机质量与箱内动态增重 | 高 | 刚体质量、接触和重心可直接仿真 |
| 刷盘/刮吸总成的高保真自建设计 | 中高 | 技术可行，但缺少可直接复用的完整工业开源URDF，CAD和参数标定工作大 |
| 20,000 m²主场积水质量守恒回收 | 高 | 赛题未要求CFD；L1稀疏水层 + 有界分段回收模型可运行且满足项目额外守恒门 |
| 全场全粒子/CFD级积水、每根刷毛刚体 | 低 | 计算量与工具成熟度不支持主场实时闭环，只能做微型验证 |
| A300满足全部任务 | 条件可行 | 干舱保持 `>=40 L`；污水舱由剩余载荷/重心反算且不超过20 L设计上限 |
| “无限接近某台实车”的校准数字孪生 | 不可证实 | 未购买除征程6外的实物，无法获得单位级标定和磨损参数 |

总体结论：**可以完成高保真、质量守恒、可运行的竞赛级虚拟样机，但不能承诺全场粒子流体或未经实物标定的数字孪生。A300暂时保留为首选，不应在污水容积、泵流量和满载账表冻结前最终定型。**

### 12.2 预计工作量

按有经验的ROS 2/Gazebo/CAD团队估算：

| 工作包 | 人周 |
|---|---:|
| 许可/BOM/四张预算表和系统布局 | `2–4` |
| A300、传感器、UR5e/2F-85集成与网格修复 | `4–7` |
| 自研承载、垃圾箱、污水箱、刷盘/刮吸CAD与Xacro | `6–10` |
| 底盘、执行器、电机、接触和故障动力学 | `5–8` |
| 水层、泵曲线、污水箱质量守恒 | `4–7` |
| MoveIt 2移动抓取、投箱和动态质量 | `4–7` |
| 全场集成、性能优化、多seed验收和文档 | `6–10` |
| 征程6/S100部署和持续运行验收 | `4–8` |
| 合计 | `35–61` 人周 |

3–4人并行且上游模型可直接使用时，首个完整高保真PC闭环约 `3–5`个月；完成正式场、多seed、性能优化和板端验收约 `6–10`个月。单人串行通常需要 `9–15`个月。若要求自制高精度工业外观网格、全粒子流体或对照实物测量，周期还会显著增加。

## 13. 已关闭的设计问题与剩余工程项

本轮三个用户问题均已关闭：

1. 干垃圾舱按赛题字面保守保证可用容积 `>=40 L`；污水舱不侵占该容积，并根据A300载荷、重心和安装空间反算，设计上限不超过20 L。
2. 清扫机构保持高精度显式建模；积水首版采用L1稀疏2.5D水层和质量守恒，不做全场粒子/CFD，L2留作后续增强。
3. 允许依据真实公开数据表自行建立并开源缺失的CAD/Xacro。

目前没有必须由用户立即回答的方案阻断。Phase 0的开源来源、侧后鱼眼、GNSS/IMU、刷盘电机、升降推杆和回收泵已经在[准备包](pre-urdf-readiness.md)中冻结；以下内容改为正式CAD/URDF期间的机器门：

- 按 Jabsco 泵曲线、吸口/刮条几何和积水深度标定实际回收速度；液位传感器在污水舱几何冻结后选取量程；
- 通过两个独立 Arducam 鱼眼、ZED-F9P与VN-100的安装遮挡和线束校核；
- 完整固定载荷和重心求解后得到的污水舱最终名义/可用容积；
- 纸板方块首版已冻结为均质实心试样；空心/填充率分布只作为后续扩展，不阻断URDF。
