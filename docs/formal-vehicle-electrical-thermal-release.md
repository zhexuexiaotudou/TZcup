# 车辆电气、线束与热设计发布边界

当前模型含 A300、UR5e 控制箱、RDK S100P、传感器、刷电机、升降、回收泵和服务机构的
几何/软件选择，以及从 `pre_urdf_contract.yaml` 追溯出的辅助负载功率账。这是功能级
仿真和设计输入，不是可制造线束包、整车电气原理图、热设计发布或实车验收。

`config/high_fidelity_vehicle/electrical_harness_thermal_readiness.yaml` 将现有功率账逐项
绑定为：UR5e 控制 350/500 W、回收泵 144/144 W、三刷 72/216 W、升降 6/30 W、MID-360
6.5/14 W、UTM-30LX 8.4/12 W、相机/定位 18/30 W、S100P 45/80 W（连续/峰值）。总计
649.9/1026.0 W 仅是源表算术和分支映射；不同轨的功率不可据此当成实测电池负载。

## 必须保持的 fail-closed 边界

- A300 的精确 VBAT、电池/BMS允许连续与峰值电流、DC/DC 拓扑和高功率隔离母线尚未冻结；
  因此牵引继承、UR5e、刷电机和回收泵没有可验证的电流、线径、压降或母线余量结论。
- S100P 的 45/80 W 为已有功率账中的 provisional 条目，而非用户自有板的输入接口、启动
  峰值或散热实测。不得推断其连接器、供电电压、外壳导热、风道或允许温度。
- 12 V/24 V 用户轨只有源合同的电压/电流上限；分支保险、导线截面积、插接件、接地/等电位、
  EMC、IP 防水、压降与热均没有 as-built 证据。
- 安全继电器、急停回路和服务执行器尚无 BOM、原理图或线束实物。它们不能由 URDF、Gazebo
  或 JSON 状态替代。

validator 仅在上述缺口被明确标为 `NOT_READY`、所有分支 `branch_ready=false`、顶层
`ready=false` 时通过。它会从 `pre_urdf_contract.yaml` 重算全部源负载，并拒绝布尔值、
NaN/Inf、分支功率漂移、超过已知 12/24 V 上游轨、遗漏负载或将未知母线伪称为可发布。

## 用户自有 S100P 与实车需要补采的证据

1. 记录实际 S100P SKU、序列号（如适用）、输入电压范围、接头型号/针脚和上电极性；在冷启动、
   ROS/感知满负荷、相机/雷达同时工作与故障恢复时，记录输入电压、电流、峰值持续时间及纹波。
2. 对 S100P、DC/DC、线束和密封计算仓在最低/最高设计环境温度、最大计算负荷及预期进水/粉尘
   条件下测量板温、外壳温、热点、风量或传导路径；给出降额、保护阈值和关机恢复行为。
3. 冻结整车单线图、保险/断路器选择、线径和长度、压降计算与测量、连接器锁止/IP 等级、
   底盘接地/屏蔽端接、EMC 预扫及安全继电器—急停断电链。
4. 以已装车的 BOM 和线束版本复测 UR5e、泵、刷、升降、传感器及服务执行器的同时运行电流，
   并验证没有超过 A300/BMS/DC/DC 的批准边界。

这些实物证据还需与质量、结构稳定性、控制标定、Gazebo 和赛题闭环的独立门共同关闭；任何一项
缺失都不能声称可制造或通过真实世界验收。
