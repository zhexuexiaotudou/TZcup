# S100P 板端优先执行边界与证据规则

生效日期：2026-08-30。用户已接通真实 RDK S100P；本文件替换“先在 PC 跑完整
计算链、再迁移到板端”的默认顺序。它不放宽任何 Gazebo 物理真值、实物安全或最终
session 绑定要求。

## 1. 执行顺序

在冻结源码、模型清单和正式 session/snapshot 已存在后，只要任务能在 S100P 上直接
完成，就先在真实板端完成，PC 不再是该计算任务的部署前置条件。推荐顺序是：

```text
冻结 source + 模型 + session/snapshot
        -> S100P 直接运行：身份、包、模型、BPU、ROS 图、性能/稳定性
        -> Gazebo：机械/接触/任务物理和随机环境真值门
        -> 同一版本的系统级集成与正式聚合
```

正式总编排的 `s100_live_runtime` 仍是 session-bound 外部硬门。现有
`--resume-s100` 是在本地门已完成后的**聚合/恢复接口**，不是要求先在 PC 跑推理的
顺序约束；板端原始采集可在 session 已建立、snapshot 已冻结后立即进行。若随后源码、
模型、词表、运行时镜像或 snapshot 改变，原板端证据失效，必须按新版本重新采集。

## 2. 必须板端优先的范围

以下工作一旦 S100P 可直接执行，必须以真实 S100P 结果为部署证据，PC 结果至多作
开发诊断或数值对照：

- S100P 身份、系统镜像、内核、ROS/TROS 与 BPU runtime 的探测；
- 官方 DOSOD、EdgeSAM、模型 HBM、词表、产品 ROS adapter 及其依赖安装；
- RGB/NV12 输入、BPU 推理、`ai_msgs` 到产品消息的转换、ROS 节点/话题/TF 图；
- DOSOD/EdgeSAM 输出率、端到端延迟、BPU/CPU/内存、温度和持续稳定性；
- ARM CPU 上的规划、状态机、抓取任务编排等**不驱动真实执行器**的软件节点。

PC/CUDA 上的 Grounding DINO、SAM 3 或 FineGrasp 可保留为能力对照、离线诊断和
仿真算法开发；它们不得被描述为 S100P 部署验收，也不得成为已可上板任务的必经步骤。

## 3. 不能改为仅板端的仿真物理真值门

以下门必须继续在 Gazebo 的当前冻结整车、随机化场景和 session 中完成；S100P 的模型
推理成功不能替代它们：

- URDF/Xacro 几何、碰撞、质量/惯量、运动包络与传感器遮挡；
- 底盘轮地接触、制动、转向、编码器/里程计与碰撞/急停联锁；
- 六轴臂关节限位、IK、全场景碰撞、夹爪接触、抓取、投箱和动态质量/重心变化；
- 刷盘/滚刷/升降/刮条接触、电机遥测、地污扫掠面积；
- 积水的地面减量、泵流量、污水箱质量守恒、满箱和排空；
- 首次建图、保存地图重启复用、随机脏污/垃圾、动态行人和 Nav2/RL 绕障闭环。

仿真真值只用于独立评测和可复算物理判定，绝不进入 S100P 或产品控制输入。

## 4. 真实硬件安全硬门

“S100P 已连接”只授权板端计算与只读诊断，不等同于传感器、底盘、机械臂、刷盘、泵或
电源链已接通。任何把真实 I/O 接到执行器的测试，必须在执行前同时满足：

1. 已确认实际接线、驱动、供电额定值、控制方向和设备序列号；
2. 实体急停可用且已验证，驱动默认禁能，存在独立的人工监护和可立即断电路径；
3. 车体位于隔离测试区；机械臂收纳、夹爪/刷盘/泵默认禁能，移动底盘悬空或被可靠限位；
4. 先完成只读传感器、零输出 topic、低功率单执行器和人工确认的逐级通电，不允许直接
   用完整任务、随机行人或自动规划驱动真实机构；
5. 每一步记录硬件配置、操作者、急停状态、命令上限、遥测、故障和安全退出结果。

在真实驱动、接线和上述安全门尚未形成证据前，板端节点只能发布观测、诊断或零执行器
命令；不得以“实机已接好”声称完成实物清扫、抓取或行驶验收。

## 5. 板端证据最低要求

每次可计入正式验收的板端运行必须保留并绑定同一 session/snapshot：设备树型号和
compatible、CPU 架构、系统/内核/ROS/TROS/runtime 版本、软件 source revision、模型与
词表 SHA-256、启动参数、ROS node/topic/type 图、BPU backend/model-info、输入与输出率、
p95 延迟、CPU/BPU/内存/温度采样、连续运行与失败/重启计数、受控停止日志。

原始 collector JSON 与验证后的 JSON 必须一起放入仓库受控、非符号链接路径；路径、摘要和
采集时间均须晚于 session start。没有真实 S100P 身份、模型哈希和运行遥测的截图、PC 日志或
手写 JSON 不构成板端通过证据。
