# 竞赛仿真演示脚本

这套流程用于展示当前已经实现的仿真链路，不等同于产品级 A–P 验收。

## 演示顺序

1. 运行 `py -3 scripts/product_acceptance.py validate-contract`，展示固定合同和标准原文哈希。
2. 使用 `scripts/run_visual_demo.ps1` 启动默认 Ackermann 车型。
3. 检查 Gazebo、RViz、TF、传感器、Nav2 与安全节点均处于活动状态。
4. 展示覆盖规划、前进式转场、动态避障、边界保护、刷盘状态和急停行为。
5. 展示地图优先的人类监督界面；未接入安全任务编排器时，任务按钮必须保持禁用。
6. 展示一次真实运行的原始日志与机器报告，说明成功项和失败项。
7. 打开 `FINAL_ACCEPTANCE_STATUS.json` 与 `FINAL_ACCEPTANCE_MATRIX.json`，逐门说明 A–P 状态。

## 必须现场声明的边界

- 当前 Ackermann 小场景虽能完成任务，但定位、重复覆盖率和效率仍未达到 V1。
- 未执行的数据集、30 种子矩阵、2 小时耐久、故障注入、回放一致性和发布冻结不得口头外推。
- 不得宣称真实域准确率、实车安全、J6 性能、真实盲审或正式产品准入已经通过。
- 演示视频、截图和单组件测试均不是综合验收替代品。
